# Cloud 9 LCD V2 Design

## Goal
Turn the AOOSTAR WTR MAX 960x376 LCD into a Cloud 9 cockpit while keeping all application code in CT130 and installing no software, daemon, or collector on the Proxmox host.

## Data architecture
- CT130 reads host-visible read-only sysfs for CPU/NVMe/RAM/GPU/block telemetry.
- CT130 uses a dedicated Proxmox API token with PVEAuditor at / for node, VM/LXC, RRD, storage, ZFS and SMART data.
- CT130 talks to application APIs over the LAN for Jellyfin/Silo, qBittorrent/Radarr/Sonarr/Seerr, Immich, AI, n8n/Postiz and monitoring sources.
- Missing/offline sources degrade to unavailable; they must never block LCD refresh.
- Secrets live outside Git in the canonical CT130 appdata tree with mode 0600.

## Display rules
- Small-screen first: one primary message per page, 2-4 secondary facts maximum.
- Prefer poster/artwork, icons, progress bars and large numerals over prose.
- High contrast, bold fonts, minimal text; every state should read in about one second.
- Cloud 9 logo is the visual identity for boot/home/editor branding.

## Core pages
1. Home: Cloud 9 logo, health, CPU temperature, RAM, network/uptime.
2. Storage: visual bay map, capacity/activity/temperature/SMART state.
3. Compute: Ryzen/Radeon activity, temperatures, VRAM/GTT and AI activity.
4. Proxmox: running guests and key platform/storage health.
5. Media: poster-first Jellyfin/Silo state; PLAYING, NEW or READY IN Xm.
6. Incoming: poster-first download/import state with percent and ETA.
7. Creator: compact active-work status from AutoSubs/n8n/Postiz/AI.
8. Mission Control: a few large, fun aggregate counts.
9. Alert: highest-priority hardware/service alert with one value and one target.

## Priority
ALERT > NOW PLAYING > AI/CREATOR ACTIVE > DOWNLOAD/IMPORT ACTIVE > JUST LANDED > normal rotation.

## Safety
- No host reboot.
- No PVE packages/services/scripts.
- Proxmox credentials read-only.
- No Docker socket from PVE exposed to CT130.
- No secret committed to Git.
