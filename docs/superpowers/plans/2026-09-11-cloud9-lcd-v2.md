# Cloud 9 LCD V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a CT130-only telemetry and small-screen presentation layer for the Cloud 9 AOOSTAR LCD.

**Architecture:** A Python telemetry sidecar inside the existing LCD container reads host-visible sysfs and calls authenticated read-only HTTP APIs. It writes normalized atomic sensor state consumed by asterctl and the WebUI; event/media rendering is introduced without moving application code onto PVE.

**Tech Stack:** Python 3.13 stdlib + Flask/Pillow already present, Proxmox HTTPS API, aoostar-rs 0.2.0, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-11-cloud9-lcd-v2.md`

## Global Constraints
- All application code stays in CT130.
- No PVE package, daemon, script or collector.
- Proxmox access is read-only PVEAuditor.
- Never commit credentials.
- UI is optimized for 960x376 and prioritizes visuals over text.
- No Cloud 9 reboot.
